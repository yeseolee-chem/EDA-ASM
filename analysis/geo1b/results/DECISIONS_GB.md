- **GB-prov** (data.py:92-131, 162-169): G2c 출처 검사. 두 G2c root가 있어야 하고, g2c worktree `results/C_select.csv`(select_g2c build가 마지막에 씀; 경로 기본값은 d0_pairs.py와 같은 `G2C_RESULTS`)가 있어야 한다. 반응마다 폴더 `.done` ⇔ C_select `chosen` ≠ '', 그리고 g2c.json의 rxn_id·src·chosen이 C_select와 같아야 한다. 하나라도 어긋나면 records.pkl도 보고서도 쓰지 않고 STOP(exit 3). 잘못된 root(예: 환경에서 넘어온 단일 run d0_g2, g2c.json 없음)나 덜 끝난 build를 조용히 쓰는 것을 막는다.

- **GB-folds** (geo_common.py:188-220): d0_folds.csv를 읽을 때 DECISIONS_PAIR P-stop의 읽는 쪽 검사를 한다(D0_pairs_report.json stop false, outputs의 d0_folds.csv sha256 = 파일). outputs 키는 절대 경로 문자열이라 파일 이름으로 찾는다. twin_of는 dtype=str, keep_default_na=False로 읽는다(RUNBOOK). 겹침 행은 fold −9·twin 없음, 나머지는 fold 0–4·component 있음이 아니면 STOP.

- **GB-core** (data.py:207): D0 core = 'D0/<component>'(설계 step 3). 겹침 5개는 component가 비어 있으므로 'D0/overlap'으로 둔다(fold −9, 어떤 집합에도 없음).
- **GB-twin-field** (data.py:146, 210): 기록에 `twin_of`(D1 rxn_id 또는 None; D1 기록은 늘 None)를 더했다. U-9b의 'fold k D1 반응의 twin' 검사와 E_rxn_d0.csv에 쓴다.
- **GB-split** (train.py:60-70): split(k): test = D1 fold k + D0 fold k(겹침 제외), inner val = D1 fold (k+1)%5만, train = 나머지 D1 fold(−1 포함) + D0 fold ≠ k. tune은 train, final은 train + inner val로 학습하므로 D0 fold k는 둘 다에 없다. 승인 설계 step 3과 명령문대로 tune에서 D0 fold (k+1)%5는 빼지 않았다(조사 'folds'의 S-A는 빼자고 했으나 승인 설계는 'fold != k'만). 한계: tune 학습에 inner-val D1 반응의 D0 twin이 들어갈 수 있다(설정·epoch 선택에만 영향, 시험 fold 누수는 아님).
- **GB-split-guard** (train.py:64-65): 겹침이 아닌 D0 기록의 fold가 0–4가 아니면(D0 fold를 모르는 예전 records.pkl, fold −1) split이 STOP(SystemExit)한다. 예전 기록으로 돌리면 D0가 모든 fold 학습에 들어가 조용히 옛 규칙으로 돌아가기 때문이다.
- **GB-final** (train.py:2-5, final 코드는 그대로): final은 eval_items(te_r)를 예측하므로 final_f{k}_s{seed}.pkl에 D1 fold k와 D0 fold k의 uid('D0_<rid>')가 함께 들어간다. 파일 이름과 launcher task 41개는 그대로다.
- **GB-baseline** (data.py:310-353): 'baseline' 명령을 data.py에 두었다(D1 run env, `jobs/cpu.slurm data.py baseline`). D 단계 끝, 학습 전에 돌린다. U-8b와 E1은 GPU env에서 같은 값을 다시 계산해 대조한다. (rev 2 정정: 같은 코드·같은 기록이므로 이것은 고정(freeze)일 뿐 독립 검사가 아니다. 독립 회귀는 GB-U8r이다.) records_sha256를 적고, D 보고서의 sha와 다르면 STOP. 파일이 이미 있을 때: 값(n, share, median, n_test)과 sha가 같으면 그대로 둔다; 값은 같고 sha만 다르면 새 sha로 다시 쓰고 previous에 옛 값을 남긴다; 값이 다르면 `--force` 없이는 STOP(학습 전 고정).
- **GB-baseline-contents** (data.py:280-291): 파일에 fold별 값, run별 시험 반응 수(n_test_by_g2c), 단일 run 참고값(geo_common G2RAW_SINGLE_RUN_REF; 아무것도 이 값과 비교하지 않음)도 적는다. 허용 오차는 GEO1 그대로(share 0.005, median 0.001 Å). geo_common의 `G2RAW_PRIMARY`는 지웠다(geo_common.py:59-64). 남은 사용처가 있으면 바로 AttributeError가 나도록 하기 위해서다.
- **GB-U8b** (tests.py:150-175): 기대값 = G2RAW_baseline.json. 그 records_sha256 = 지금 records.pkl, n_test도 같아야 한다. 라벨 형성 거리 대 C_compare d_dft는 처음 300 시험 반응(전과 같음). G2 형성 거리 대 C_compare d_g2는 g2c == 'orig'인 처음 300 반응만(C_compare d_g2는 단일 run D1-G2 TS). 대조할 반응이 0개이거나 C_compare 값이 NaN이면 inf로 FAIL로 만들었다(원래 코드의 `max(dev, nan)`은 NaN을 조용히 넘겼다). 모든 시험 반응에 g2c run이 있어야 한다.
- **GB-U9b** (tests.py:176-231): 더한 검사 — 겹침 수 = D 보고서 d0_overlap이고 fold −9; 비겹침 D0는 fold 0–4·core 'D0/'; twin fold = D1 twin fold; fold k의 tune·final 학습(tr + va)에 fold k D0나 fold k D1 반응의 twin 없음(rev 2 정정: 처음 판은 twin_of 하나만 보아 data.py가 이미 같게 만든 값이라 늘 참이었다. 지금은 PAIR rev 2 P-u9b대로 d0_twins.csv 전체 표를 본다); inner val은 D1만; test = D1 fold k + D0 fold k; 겹침은 train·val·test 어디에도 없음; G2c TS가 있는 비겹침 D0는 5 fold를 합쳐 정확히 한 번, 자기 fold 모델이 예측. '시험 입력 = G2'와 '결합 그래프 = 입력' 검사는 D1 200개 + D0 200개로 넓혔다.
