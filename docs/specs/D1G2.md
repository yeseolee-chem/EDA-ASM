# D1-G2 — SMILES에서 출발한 xTB 구조(G2)와 그 위의 feature·HF EDA (전체) — Claude Code 실행 지시서

**저장소:** `d1-hf` 브랜치 HEAD에서 새 브랜치 **`d1-g2`**를 만들어 commit한다. `d1-hf`에는 `analysis/d1_pair/`와 `analysis/d1_hf/` 코드가 모두 있다.
**이 파일:** `docs/specs/D1G2.md`로 commit한다.
**새 코드:** `analysis/d1_g2/` · **결과:** `analysis/d1_g2/results/` · **scratch:** `/gpfs/tmp_cpu2/yeseo1ee/d1_g2/` (이하 `$G2`)
**순서:** X(입력) → T(회귀 검사) → S(smoke 10반응, 통과하면 자동 진행) → G(G2 구조 전체) → C(G1·DFT TS와 비교) → F(xTB feature) → H(HF EDA) → A(정답 짝 차이와 비교) → R(보고)
**사용자 승인으로 멈추는 곳은 없다.** 12절 STOP 조건에서만 멈추고 묻는다. 버그를 찾으면 고치기 전에 보고한다.
**D1HF는 계속 돈다.** D1HF job을 취소하거나 그 scratch를 건드리지 않는다. 남는 job 자리를 쓴다.

---

## 0. 무엇을, 왜

- 지금까지의 feature(G1)는 DFT TS에서 출발해 xTB로 다시 최적화한 구조에서 나왔다. 새 반응에는 DFT TS가 없으므로, 실제로 쓸 모델의 입력은 **반응 SMILES에서 xTB만으로 찾은 TS(G2)**에서 나와야 하고, 학습도 같은 입력으로 해야 한다.
- 이 명령서는 D1 라벨 반응 전부에 대해 G2 구조를 만들고, 그 위에서 모델 입력 세 가지를 모두 계산한다.
  1. 원자 카드(FU2 토큰)
  2. 전역 feature 182개
  3. HF/6-31G\* EDA 8채널 + barrier
- 근거: D1 검증(`D1_build/validation/results/VALIDATION_REPORT.md`, 브랜치 d1-build)에서 같은 반응을 SMILES부터 다시 돌렸을 때 같은 TS를 찾은 비율은 0.50이었다. 반면 같은 TS에서 출발해 엔진만 바꿨을 때 TS는 0.009 Å만 움직였다. G1은 라벨과 같은 TS를 물려받으므로, G1 기반 성능은 실제 사용보다 낙관적일 수 있다.
- 모델 학습·평가는 이 명령서에 넣지 않는다. 이 명령서의 결과가 나온 뒤 사전 등록(ADD3)과 함께 따로 지시한다.

## 1. 범위

- 대상 = `labels_d1.json`(9,496행, 모두 status ok)에서 skeleton이 `DppC`·`DppT`(D'')가 아닌 행 전부. 로더는 `d1pair_common.load_d1_labels()`, 제외 목록은 `d1pair_common.DPP`이다.
- D1HF의 DFT 구조 대상(9,266)과 같은 목록이어야 한다. 다르면 STOP.
- 반응마다 D1 본계산이 autodE에 준 것과 **같은 입력**을 쓴다. 반응 SMILES, 요청한 위치·입체 이성질체(생성물 SMILES), 전하·다중도가 그것이다. 출처 파일(D1 run의 작업 목록·매니페스트)과 sha256을 X 보고에 적는다.

## 2. 방법 (고정)

**D1 본계산과 같은 것:**
- autodE 버전(1.4.5)과 환경. D1 run의 환경 스크립트를 그대로 쓰고, 버전을 기록한다.
- 절차: `ade.Reaction(rxn_smiles, solvent_name="water", temp=298.15)` → `calculate_reaction_profile(free_energy=True)`. `hmethod_conformers = False`이고, conformer는 xTB(lmethod)로 고른다.
- autodE 코드는 고치지 않는다. 무작위 seed가 고정되지 않은 것도 D1과 같게 둔다.
- 입체 확인(`stereo_check`)과 TS gate(`run_ts.analyse`, F1 허수 규칙 포함)를 그대로 쓴다.
- 반응당 1회만 돈다. 인프라 오류(ORCA MPI 시작 실패 등)일 때만 같은 입력으로 한 번 더 돌린다(D1의 `retry_infra_once` 규칙).

**D1과 다른 것 (수준만 바꾼다):**

| 항목 | D1 본계산 | G2 |
|---|---|---|
| autodE hmethod의 모든 ORCA 계산 (low_opt, opt, opt_ts, grad, hess, sp) | B3LYP D3BJ def2-SVP/TZVP, SMD(water) | **`XTB2 ALPB(water)`만**. 범함수·기저·CPCM·SMD 단어 없음 |
| OptTS 블록 | Recalc_Hess 30, Trust −0.1, MaxIter 100 | G1과 같음: `%geom Calc_Hess true Recalc_Hess 5 MaxIter 200 end` |
| 기준 구조 (`make_reference`) | Coley `_alt` 규칙, 마지막 최적화와 ΔG 비교는 DFT | **같은 규칙, DFT 단계를 xTB로**: 최적화 = `xtb --opt tight --alpb water --gfn 2`, ΔG = `xtb --ohess --alpb water`의 자유에너지. 문턱(RMSD > 0.05 Å, ΔG < −0.239 kcal/mol)은 그대로 |
| dipolarophile 기준 구조 | autodE 반응물 | autodE 반응물 (xTB 수준) |

- 설정은 `pilot_common.configure_autode`를 그대로 부르고, 새 config 파일로 키워드만 바꾼다.
- autodE가 용매 키워드를 자동으로 붙이는 방식 때문에 `XTB2 ALPB(water)`만 남게 할 수 없으면, **우회 코드를 쓰지 말고 STOP**.
- D1 run 코드(`d1pair_common.D1_RUN` 아래의 `run_ts`, `stereo_check`, `make_reference`, `pilot_common`)는 import만 하고 복사·수정하지 않는다. 바꿔야 하는 부분(기준 구조의 DFT 단계)은 `analysis/d1_g2/`의 wrapper에 둔다.

**출력 형식:** G1과 같은 폴더 형식으로 쓴다. `$G2/g2_final/<rxn_id>/{ts.xyz, ts.hess, rel1.xyz, rel2.xyz, result.json}`과 `.done` 또는 `.fail_<이유>`.
- 같은 형식이면 기존 feature 코드와 D1HF runner를 **입력 루트만 바꿔** 그대로 쓸 수 있다.
- `result.json`에는 상태, 허수 진동수, 입체 판정, autodE 버전, 단계별 코어시간, 원자 순서 처리(아래)를 넣는다.

**원자 순서:** feature 코드는 TS 원자 순서가 라벨과 같다고 가정한다(G1이 그랬다).
- G2 TS의 원소 순서와 반응 중심 원자 쌍(`formed_pairs_ts`)이 라벨과 같으면 그대로 쓴다.
- 다르면 반응 중심을 고정한 무거운 원자 그래프 동형으로 라벨 순서에 다시 매긴다. `result.json`에 `remapped: true`를 적는다.
- 동형이 없으면 `.fail_order`로 처리한다.

## 3. Phase X — 입력

1. 대상 목록, 반응별 autodE 입력(SMILES, 요청 이성질체, 전하·다중도)을 모아 `results/X_targets.csv`로 쓴다.
2. 입력이 D1 run이 실제로 쓴 것과 같은지 확인한다. 각 행의 D1 job 폴더 기록과 비교하고, 하나라도 다르면 STOP.
3. 출력: `results/X_report.json`(대상 수, 출처 파일 sha256).

## 4. Phase T — 회귀 검사 (G2 계산 전, 기존 결과를 다시 만들 수 있는지)

입력 루트만 바꿔 기존 코드를 쓰는 경로가 계산을 바꾸지 않는지 G1 폴더로 확인한다.

| # | 검사 | 통과 기준 |
|---|---|---|
| T-1 | 전역 182 feature 경로(`d1_features`, Phase F 방식)를 루트 인자로 G1 폴더 5반응에 돌림 | `X182_d1.parquet`의 같은 행과 1e-8 안에서 같음 |
| T-2 | FU2 원자 값·토큰 경로(`fu2/atoms.py`, `fu2/tokens.py`)를 루트 인자로 G1 폴더 5반응에 돌림 | 토큰 npz sha256이 `results/fu2/T_manifest.csv`와 같음 |
| T-3 | D1HF runner를 `geom=g2` 경로 그대로, 입력 폴더만 G1으로 3반응 | D1HF의 HF@G1 값과 1e-6 kcal/mol 안에서 같음 |

하나라도 실패하면 STOP.

## 5. Phase S — smoke 10반응 (통과하면 사용자 승인 없이 G로 진행)

- 고르는 법: dipole 5종마다 2개, `numpy.random.default_rng(20261022)`. F, Si, S, Cl, Br 중 빠진 원소가 있으면 그 원소를 가진 반응으로 바꾼다. 목록은 `results/S_list.csv`.
- 확인:

| # | 확인 | 기준 |
|---|---|---|
| S-1 | autodE가 만든 ORCA 입력 전부 | `XTB2`와 `ALPB(water)`가 있고, B3LYP·def2·CPCM·SMD가 없음. 예시 입력 하나를 보고서에 그대로 붙인다 |
| S-2 | 기준 구조 wrapper | DFT 계산 0회, xtb 최적화·ohess가 실제로 돔 |
| S-3 | 출력 형식 | 10개 모두 `g2_final/` 형식. ok인 반응은 T-1·T-2·T-3 경로로 feature와 HF까지 끝까지 계산됨 |
| S-4 | 성공 | ok ≥ 7 / 10, 파이프라인 오류 0 |
| S-5 | 비용 | 반응당 코어시간과 원자 수 관계를 맞춰, 전체 예상 코어시간을 보고 |

- S-1–S-4가 모두 통과하고 S-5의 예상이 **50,000 코어시간 이하**면 보고만 하고 G로 간다. 아니면 STOP.

## 6. Phase G — G2 구조 전체

- 대상 전부. smoke에서 끝난 반응은 건너뛴다(멱등).
- 순서: D1PAIR 기준 짝 반응 → anchor 계열 반응 → 나머지(job_id 순). D1PAIR 짝에 쓰이는 반응이 먼저 끝나게 하기 위해서다.
- 작업 풀: 48코어 노드 job 하나에서 반응 여러 개를 동시에 돌린다(반응당 코어 수는 S 단계 시간으로 정하고 기록).
- 중간 점검(끝난 반응 1,000개마다): ok 비율, 실패 이유별 수, 인프라 실패 비율, 원자 순서 다시 매김 비율. `results/G_interim_<k>.md`.
- 출력: `results/G_status.csv`(rxn_id, job_id, status, 실패 이유, remapped, 코어시간), `results/G_report.json`.

## 7. Phase C — G2를 G1·DFT TS와 비교 (구조만, 설명용)

- 비교 방법: D1 검증의 TS 비교 규칙(`VALIDATION_SPEC.md` 6.4: 무거운 원자 그래프 동형 + 거울상을 고려한 Kabsch RMSD, "같은 TS" 판정 기준)을 그대로 쓴다.
- 보고(G2 ok 반응, dipole·골격·위치별로도):
  - G2 = DFT TS("같은 TS") 비율, G2 = G1 비율
  - 무거운 원자 RMSD 분포(중앙값, 90 %)
  - 형성 결합 길이 차이
  - 기준 구조 RMSD (G2 rel 대 G1 rel)
  - G2 실패 반응의 특징(작용기, 골격)
- 출력: `results/C_compare.csv`, `results/C_summary.md`.

## 8. Phase F — G2 위 xTB feature

- 전역 182: T-1 경로로 G2 ok 반응 전부 → `$G2/X182_d1_g2.parquet`. 열 순서는 `X182_d1.parquet`와 같고, sha256을 기록한다.
- FU2 원자 값·토큰: T-2 경로로 → `$G2/fu2/`. 버전 이름은 `fu2-atoms-3-g2`, `fu2-tokens-3-g2`로 하고, Q·T 단계의 gate를 그대로 적용한다. `results/F_tokens_manifest.csv`.
- 출력: `results/F_report.json`(반응 수, 실패 이유, sha256).

## 9. Phase H — G2 위 HF EDA

- D1HF와 **같은 계산 5개**: EDA 1 + 조각 단일점 4. 방법은 `HF D3BJ 6-31G* SMD(water) NoSym TightSCF`이고, 조각·전하·다중도는 라벨 입력과 같다.
  - 좌표만 바꾼다. `eda`와 `frag*_dist`는 G2 TS에서, `frag*_rel`은 G2 기준 구조(`rel1.xyz`, `rel2.xyz`)에서 가져온다.
- D1HF runner·조립·gate(g1_asm, g2_sum, g3_seam, g_enuc, g_setting, orca)를 그대로 쓴다(`geom = g2`).
- 출력: `$G2/labels_d1_hf_g2.json`, `results/labels_d1_hf_g2.parquet`, `results/H_status.csv`.

## 10. Phase A — 정답 짝 차이와 비교 (설명용, 사전 등록 아님)

D1HF Phase A와 같은 방법을 쓴다.
- 짝: D1PAIR P_main 기준 짝 중 a·b 모두 G2 ok인 짝.
- 타깃마다 정답 ΔΔ = β × HF ΔΔ를 **절편 없이** 맞춘다. `fold_T1`의 학습 쪽에서 맞추고 시험 쪽에 적용한다.
- 보고: 시험 MAE(전체·para), null MAE, 상관 r.
- **같은 짝에서 나란히** 보고한다: HF@DFT TS, HF@G1, HF@G2, 그리고 FU2 GNN-A+G(G1 입력).
- para MAE 구간 표시: ≤ 0.13, ≤ 0.26, ≥ 0.6. 결론은 쓰지 않는다.
- 추가 설명용: 짝 ΔΔ 오차를 "G2가 라벨과 같은 TS를 찾은 짝"과 "다른 TS를 찾은 짝"으로 나눠 따로 보고한다.
- 출력: `results/A_pairs.csv`, `results/A_summary.csv`, 그림 `results/figA_g2.png`(타깃별 HF ΔΔ 대 정답 ΔΔ, para 짝, 세 구조를 나란히).

## 11. Phase R — `results/RUN_REPORT_G2.md` (한국어)

- 맨 앞 세 문장:
  1. G2 성공 반응 수와 성공률
  2. G2가 라벨과 같은 TS를 찾은 비율
  3. Phase A의 oi·cpcm para MAE (DFT TS / G1 / G2)
- 절: X → T → S → G → C → F → H → A → 실패·재시도 → 비용 → 한계.
- 한계에 꼭 적을 것:
  - autodE seed가 고정되지 않아 다시 돌리면 다른 TS가 나올 수 있다(D1 검증 V3: 같은 TS 0.50).
  - 기준 구조 규칙의 DFT 단계를 xTB로 바꿨다.
  - G2 실패 반응은 배포 때도 예측할 수 없는 반응이다.
- 수치는 모두 파일에서 옮긴다.

## 12. 자원과 실행 (HPC)

- python, autodE, ORCA, xtb는 모두 `sbatch`(`--time=48:00:00`)로만 돌린다. 로그인 노드에서는 편집·git·`squeue`·`scancel`·`sbatch`만 한다.
- MaxJobs 10, MaxSubmit 20(배열 원소 포함). D1HF job이 쓰는 자리를 빼고 남는 자리만 쓴다.
- 파티션 `cpu1,cpu2`. ORCA는 `jobs/g_env.sh`의 6.1.1(`/home1/yeseo1ee/orca_6_1_1_avx2`), xtb 6.7.1이다.
- 48시간 안에 못 끝나면 같은 명령으로 다시 제출한다(멱등, 반응 폴더 단위 원자적 쓰기).
- 비용 참고(추정): D1HF 파일럿 실측으로 HF 계산 5개는 반응당 0.106 코어시간(중앙값), 전체 약 1,400 코어시간이다. xTB 수준 autodE 비용은 S-5에서 실측한다.

## 13. 규칙

- 읽기만: `labels_d1.json`, D1 run 폴더와 코드, D1 job 폴더, `d1_pair/` scratch(G1 포함)와 결과, `d1_hf/` scratch와 결과.
- 새 파일은 `analysis/d1_g2/`, `$G2/`, 이 명령서에만 쓴다. 기존 feature·토큰 코드에 루트 인자가 없으면, 기본 동작이 바뀌지 않게(기본값 = 기존 경로) 인자만 추가하고 T 검사로 확인한다.
- 방법·문턱·gate를 결과를 본 뒤 바꾸지 않는다. 바꿀 필요가 보이면 STOP.
- 원자적 쓰기, 멱등. 수치는 파일에서 옮긴다.

## 14. STOP

| 단계 | 조건 |
|---|---|
| X | 대상 목록이 D1HF의 9,266과 다름; autodE 입력을 D1 run 기록과 맞출 수 없음 |
| T | T-1–T-3 중 하나라도 실패 |
| S | S-1–S-4 중 하나라도 실패; 전체 예상 > 50,000 코어시간; autodE가 `XTB2 ALPB(water)`만으로 돌게 설정할 수 없음 |
| G | 1,000개 단위 점검에서 ok < 70 %, 또는 인프라·파이프라인 실패 > 2 %; `.fail_order` > 1 % |
| F, H | 각 단계의 기존 gate 실패율 > 1 % |
| 언제든 | 이 문서에 없는 방법 변경이 필요해 보임 |

STOP하면 무엇이 어긋났는지, 해당 파일과 줄, 가능한 선택지를 적어 보고하고 기다린다.
